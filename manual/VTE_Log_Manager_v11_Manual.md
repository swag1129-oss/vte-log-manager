# VTE Log Manager v11 사용자 매뉴얼 (PC + 폰 앱)

이 문서는 A222 VTE 증착 기록용 VTE Log Manager v11(PC)과 폰 웹앱(PWA)의 사용법을 정리한 것이다. v9 매뉴얼(`vte_manager_v9_manual_draft.md`)과 v10 업데이트 노트(`vte_manager_v10_update_notes.md`)를 바탕으로 하고, 현재 코드(`src/desktop`, `src/mobile`, `src/core/vte-core.js`)를 기준으로 작성했다. 문서와 앱 동작이 다르면 앱 동작이 맞다.

## 1. 개요

### 1.1 구성

| 구분 | 이름 | 실행 방법 | 데이터 접근 |
|---|---|---|---|
| PC | VTE Log Manager v11 | Windows 설치본 또는 `vte_manager_v11.html`을 Chrome/Edge로 열기 | PC의 Dropbox 폴더를 직접 읽고 씀 |
| 폰 | VTE Log (PWA) | https://swag1129-oss.github.io/vte-log-manager/ 를 홈 화면에 추가 | 랩 공용 Dropbox 계정으로 로그인해 인터넷으로 읽고 씀 |

두 앱은 같은 폴더, 같은 Excel 양식을 쓴다. 폰에서 저장한 로그는 PC에서 그대로 보이고, PC에서 만든 로그는 폰에서 그대로 보인다.

### 1.2 데이터 폴더

기준 폴더는 Dropbox의 다음 위치다.

```text
/NEXT LAB/Log/A222/VTE log/VTE_MANAGER
```

| 하위 폴더 | 내용 | PC | 폰 |
|---|---|---|---|
| `Process_General/20YY/YYMMDD/` | 일반증착 로그 | 읽기/쓰기 | 읽기/쓰기 |
| `Process_Tooling/20YY/YYMMDD/` | 툴링 로그 | 읽기/쓰기 | 읽기/쓰기 |
| `Calibration/<재료명>/YYMMDD.xlsx` | 재료별 calibration | 읽기/쓰기 | 읽기/쓰기(실측 추가) |
| `Structures/` | OLED structure 파일 | 읽기/쓰기 | 프리셋 목록에 표시(읽기) |
| `Presets/<이름>.xlsx` | 증착 구조 프리셋 (v11 신규) | 저장 | 읽기/저장/삭제 |
| `_mobile_test/` | 폰 테스트 모드 전용 폴더 | 사용 안 함 | 테스트 모드일 때만 |

폰 앱은 이 기준 폴더 밖의 파일은 읽지도 쓰지도 않는다. 경로 검사는 코드에서 요청 전에 막는다.

### 1.3 폰 앱에서 할 수 있는 것 / 없는 것

할 수 있는 것:

- 로그 조회(검색, 일반/툴링 필터, 상세 보기, 구조 그림)
- 새 일반증착/툴링 로그 기록(시작/끝 시각, 측정값, 공증착)
- 기존 로그 수정, 삭제
- 프리셋에서 기록 시작, 프리셋 저장/삭제
- Calibration 조회, 모니터 두께/레이트 계산, 실측 추가
- 오프라인 기록 후 나중에 자동 업로드

폰에서 하지 않는 것:

- OLED Structure 계산/시각화 (PC 전용)
- Calibration 파일 수정/삭제 (PC에서)

## 2. 설치와 첫 실행

### 2.1 폰 (iPhone)

1. Safari로 https://swag1129-oss.github.io/vte-log-manager/ 를 연다. (Chrome 등 다른 브라우저 말고 Safari)
2. 아래쪽 공유 버튼을 누른다.
3. `홈 화면에 추가`를 누르고 `추가`를 누른다.
4. 홈 화면의 `VTE Log` 아이콘으로 앱을 연다. 이후에는 항상 이 아이콘으로 연다.
5. `Dropbox 로그인`을 누르고 랩 공용 Dropbox 계정으로 로그인한 뒤 접근을 허용한다.
6. `작성자 이름` 화면에서 본인 이름을 입력하고 `저장`을 누른다.
7. 로그 목록 화면이 나오고 상단에 `Dropbox 목록 확인 중…`, `받는 중 n/N`이 표시된다. 첫 동기화는 파일 수에 따라 시간이 걸린다.

### 2.2 폰 (Android)

1. Chrome으로 https://swag1129-oss.github.io/vte-log-manager/ 를 연다.
2. 오른쪽 위 메뉴(⋮)에서 `앱 설치` 또는 `홈 화면에 추가`를 누른다.
3. 홈 화면의 `VTE Log` 아이콘으로 앱을 연다.
4. 이후 과정은 iPhone의 5~7번과 같다.

참고:

- 작성자 이름은 이 기기에만 저장되고, 저장하는 파일에 기록된다. `설정 > 작성자`에서 바꿀 수 있다.
- 로그인 정보도 기기(앱)별로 저장된다. Safari에서 로그인했더라도 홈 화면 아이콘에서 다시 로그인해야 할 수 있다.

### 2.3 첫 실행 후 확인할 것: 저장 위치

폰 앱은 처음 설치하면 **실제 로그 폴더에 저장**한다. 연습하고 싶으면 `설정 > 저장 위치`에서 테스트 모드를 켠다. 테스트 모드에서는 저장한 파일이 `VTE_MANAGER/_mobile_test/` 안에만 생긴다(3.7.1 참고).

- 연습할 때만 테스트 모드를 켜고, 끝나면 끈다.
- `기록` 탭 첫 화면에 현재 저장 위치가 표시된다.
  - `테스트 모드: 저장하면 VTE_MANAGER/_mobile_test/ 안에만 생겨요 (설정에서 변경).`
  - `실제 로그 폴더에 저장돼요.`

### 2.4 PC (Windows 설치본)

1. 배포된 ZIP 파일을 마우스 오른쪽 버튼으로 눌러 `압축 풀기`를 한다. (ZIP 안에서 바로 실행하지 않는다.)
2. 압축을 푼 폴더에서 `INSTALL_WINDOWS.cmd`를 더블클릭한다.
3. 설치가 끝나면 바탕화면에 `VTE Log Manager` 바로가기가 생기고 앱이 한 번 열린다.
4. 앱 위쪽의 `폴더 선택`을 누른다.
5. Dropbox 안의 `NEXT LAB > Log > A222 > VTE log > VTE_MANAGER` 폴더를 선택한다.
6. 브라우저가 폴더 읽기/쓰기 권한을 물으면 허용한다.
7. 상단에 `선택됨: VTE_MANAGER / 로그 n개 / 재료 n개`가 나오면 완료다.

참고:

- 설치 위치: `%LOCALAPPDATA%\VTE Log Manager`
- 설치 프로그램은 `내 문서\VTE Log Data` 폴더(혼자 쓰기용)도 만들고 탐색기로 열어 준다. 랩 Dropbox와 같이 쓰려면 이 폴더가 아니라 5번의 Dropbox `VTE_MANAGER`를 선택한다.
- Chrome 또는 Edge가 필요하다. Firefox에서는 폴더 읽기/쓰기가 안 된다.
- Windows 설치본은 Excel 라이브러리(SheetJS)를 함께 넣어 두어 인터넷 없이 동작한다.
- 앱을 새로 열 때마다 `폴더 선택`을 다시 해야 한다.

### 2.5 PC (Mac 또는 설치본 없이)

1. Chrome에서 `vte_manager_v11.html`을 연다.
2. 2.4의 4~7번과 같이 폴더를 선택한다.

이 단일 HTML 파일은 SheetJS를 인터넷(CDN)에서 불러오므로 인터넷 연결이 필요하다.

## 3. 폰 앱 사용법

### 3.1 화면 구성

- 상단: 앱 이름, 동기화 상태 문구, 동기화 버튼(⟳)
  - 상태 문구 예: `로그 812개 · 9. 17. 오후 02:10 동기화`, `오프라인 — 캐시된 데이터 표시 중`
  - 상태 문구를 누르면 마지막 오류 내용을 볼 수 있다.
- 상단 배너(필요할 때만): `새 버전이 있어요 · 적용`, `업로드 대기 n건 · 보기`
- 오른쪽 위 구조 패널(기록 중, 로그 상세에서): 적층 구조 그림
- 하단 탭: `로그`, `기록`, `Calibration`, `설정`

앱을 열 때와 인터넷이 다시 연결될 때 자동으로 동기화한다. 바뀐 파일만 새로 받는다. 받은 데이터는 폰에 저장되므로 오프라인에서도 조회할 수 있다.

### 3.2 로그 탭

#### 3.2.1 목록

1. `로그` 탭을 누른다.
2. 검색창에 재료명이나 파일명 일부를 입력한다(예: `CBP`). 파일명과 경로만 검색한다.
3. `전체` / `일반` / `툴링`으로 종류를 고른다.
4. 목록은 100개씩 보이며, 맨 아래 `더 보기`로 더 불러온다.

각 항목에는 날짜(`2026-09-17` 형식), 종류 배지, 파일명이 보인다. 테스트 폴더 파일에는 `테스트` 배지가 붙는다.

#### 3.2.2 상세 보기

항목을 누르면 상세 화면이 열린다.

- 재료·포트 목록
- 작성 정보: `작성 <이름> · <작성 시각> · 수정 <이름> <수정 시각> · 프리셋 <이름>` (폰에서 저장한 파일만)
- 레이어별 카드: 진공, 파워, 온도, 레이트(시작 → 끝), 모니터, 실측, 목표 실제, 필요 모니터, Ratio, TF, 메모
- 오른쪽 위 구조 패널: 레이어 블록을 누르면 해당 레이어 카드로 이동. 공증착은 한 블록 안에 재료별로 나뉘어 그려진다.
- 맨 아래: 파일 경로

#### 3.2.3 로그 수정

1. 상세 화면에서 `수정`을 누른다.
2. `기록` 탭으로 이동하며 제목에 `수정 중: <파일명>`이 표시된다.
3. 값을 고친 뒤 `Dropbox에 저장`을 누른다.

저장 결과:

- 같은 파일에 덮어쓰는 경우: 날짜와 로그 종류(일반/툴링)를 바꾸지 않았고, 파일이 아직 있으며, 테스트 모드 상태가 원래 파일과 맞을 때(실제 파일은 테스트 모드 끔, 테스트 파일은 테스트 모드 켬).
- 새 파일로 저장되는 경우: 위 조건이 하나라도 안 맞을 때. `새 파일로 저장했어요. 원래 파일(...)은 그대로 있어요.`가 표시된다.
- 다른 기기에서 먼저 수정된 경우: `다른 기기에서 먼저 수정된 로그예요. 덮어쓰지 않고 새 파일로 저장할까요?`가 뜬다. 확인하면 새 파일로 저장된다(6.3 참고).

수정 저장 시 파일 1행에 `Modified By`, `Modified At`이 추가되고 원래 `Author`, `Created At`은 유지된다. 이전 내용은 Dropbox 버전 기록에서 복구할 수 있다.

PC 양식이 아닌 오래된 파일은 레이어를 읽지 못할 수 있다. 이때 `이 파일은 매니저 양식이 아니라 레이어를 불러오지 못했어요. 빈 로그로 수정할까요?`가 뜬다. 보통은 취소한다.

#### 3.2.4 로그 삭제

1. 상세 화면에서 `삭제`를 누른다.
2. 확인창에서 파일명을 확인하고 확인을 누른다.
3. 실제 로그 폴더 파일이면 한 번 더 확인한다.

- 삭제한 파일은 Dropbox 휴지통에서 복구할 수 있다.
- 테스트 모드에서는 실제 폴더 파일을 지울 수 없다.
- 오프라인에서는 삭제할 수 없다.
- 그 사이 다른 기기에서 수정/삭제된 파일이면 삭제하지 않고 알려 준다. 동기화 후 다시 확인한다.
- 이 로그를 수정 중인 초안이 있으면 초안도 함께 버릴지 묻는다.

### 3.3 기록 탭

#### 3.3.1 기록 시작

`기록` 탭 첫 화면에는 세 가지 시작 방법이 있다.

- `일반증착 새 로그`
- `툴링 새 로그`
- `프리셋에서 시작`: 목록에서 프리셋을 찾아 `일반증착으로` 또는 `툴링으로`를 누른다(3.4 참고).

이미 입력 중인 초안이 있으면 `작성 중인 초안이 있어요. 버리고 새로 시작할까요?`를 묻는다. 초안은 한 번에 하나만 유지된다.

#### 3.3.2 상단 입력

- `일반증착` / `툴링`: 로그 종류. 기록 중에도 바꿀 수 있다.
- `날짜 (YYMMDD)`: 오늘 날짜가 자동 입력된다. 저장 폴더와 파일 날짜가 된다.
- `프리셋`: 프리셋에서 시작했으면 이름이 표시된다(읽기 전용).
- `메모 (모든 레이어 Notes에 붙음)`: 모든 레이어 비고 뒤에 ` / 메모` 형식으로 붙는다.
- 오른쪽 배지: `저장 중…` → `초안 저장됨`

#### 3.3.3 마스크 홀더

마스크 홀더는 9칸이고, 칸 번호는 왼쪽 위에서 오른쪽 아래로 센다.

```
1 2 3
4 5 6
7 8 9
```

각 칸에 들어갈 수 있는 것은 네 가지다.

| 표시 | 뜻 | 파일 기록 |
| --- | --- | --- |
| `전면` | 빈칸. 마스크 없이 기판 전체에 증착된다. | `.` |
| `O` | Organic Mask | `O` |
| `M` | Metal Mask | `M` |
| `―` | 블록. 이 칸에는 아무것도 올라가지 않는다. | `B` |

입력은 두 단계다. 한 홀더에 Organic Mask와 Metal Mask를 섞어 쓰는 일은 거의 없으므로, 먼저 그 홀더의 마스크 종류를 `전면`/`O`/`M` 중에서 고르고, 그다음 격자에서 막을 칸을 누른다. 누른 칸은 `―`(블록)가 되고 다시 누르면 고른 마스크로 돌아온다. 종류를 바꿔도 막아 둔 칸은 그대로 유지된다.

`반전`은 블록과 사용 칸을 뒤집는다. 두 번째 홀더가 첫 번째 홀더가 막은 자리를 덮는 흔한 경우에 쓴다.

한 홀더에 서로 다른 마스크를 섞어야 하면 파일을 직접 고쳐야 한다. 앱에서 그 홀더의 종류를 다시 고르면 막지 않은 칸이 모두 같은 마스크로 바뀐다.

홀더는 `Mask1`/`Mask2`/`Mask3` 세 개까지 쓸 수 있고, 배치는 증착마다 다르므로 로그를 쓸 때마다 입력한다. 레이어의 마스크 선택(`M1`/`M2`/`M3`)이 어느 홀더를 쓴 것인지 가리킨다. 쓰는 레이어가 없는 홀더는 흐리게 표시된다.

배치는 파일 1행 메타에 `Mask1 Cells` 같은 이름으로 9칸 문자열로 저장된다. 예를 들어 4·5·7·8번을 막고 나머지에 Organic Mask를 끼웠다면 `OOOBBOBBO`다. 9칸이 모두 빈칸이면 기본값이라 파일에 쓰지 않는다.

한 번의 증착에서 서로 다른 샘플을 만들 때 이 배치가 근거가 된다. 위 예시에서 `Mask1`으로 올린 층은 1·2·3·6·9번 기판에만, 반대 배치인 `Mask2`로 올린 층은 4·5·7·8번 기판에만 올라간다. 같은 칸이 홀더마다 다른 마스크를 가질 수도 있고, 그 기판은 두 층을 모두 받는다.

#### 3.3.4 샘플 종류와 ID

홀더 배치에 따라 기판마다 실제로 올라간 층이 달라진다. 앱은 9칸을 각자 받은 적층으로 묶어서 **샘플 종류**를 계산한다. 종류마다 `<Process ID>-T1`, `-T2`, `-T3` 형식의 ID가 붙는다.

예를 들어 공통층을 전면으로 올리고, `Mask1`으로 한 층, 반대 배치인 `Mask2`로 다른 층을 올리면서 9번 칸만 두 홀더 모두 열려 있었다면 세 종류가 나온다.

| ID | 기판 | 적층 |
| --- | --- | --- |
| `…-T1` | 1, 2, 3, 6 | 공통층 + Mask1 층 |
| `…-T2` | 4, 5, 7, 8 | 공통층 + Mask2 층 |
| `…-T3` | 9 | 공통층 + 양쪽 층 |

번호는 그 종류가 처음 나타나는 칸 순서로 매긴다. 같은 로그를 다시 저장해도 배치를 바꾸지 않았다면 ID는 그대로다. 종류를 가르는 기준은 받은 층의 적층이고, 그 층이 Organic Mask를 거쳤는지 Metal Mask를 거쳤는지는 구분하지 않는다. 아무 층도 받지 않은 칸은 샘플이 아니고 로그 상세에 `증착 없음`으로 표시된다.

종류가 둘 이상이면 로그 상세에 ID와 기판 번호가 표시되고, 파일 1행 메타에 `Samples` 이름으로 `T1=1,2,3,6; T2=4,5,7,8; T3=9` 형태로 저장된다. 종류가 하나뿐이면 표시하지 않는다.

오른쪽 위 구조 패널에도 종류가 둘 이상일 때 `T1` `T2` `T3` 탭이 생긴다. 탭을 누르면 그 종류의 적층만 그려지고, 아래에 해당 기판 번호가 표시된다. 그 종류가 받지 않은 층은 그림에서 빠진다. 기록 화면과 로그 상세 모두 같은 방식이다.

#### 3.3.5 레이어 카드 읽는 법

카드 한 장이 레이어 하나다.

1. 제목 줄
   - `▾ 1. 재료명 소스` : 재료명은 빨간색으로 표시된다. 제목을 누르면 카드가 접히고 펼쳐진다.
   - 마스크 선택(`M1`/`M2`/`M3`)
   - `↑` `↓`: 순서 이동, `✕`: 레이어 삭제(값이 있으면 확인)
2. 요약 줄: `모니터 42.1nm · 0.5→0.5Å/s`와 경과/소요 시간
3. 파란 상자(목표 → 모니터)
   - 왼쪽 칸에 목표 실제 두께(nm)를 입력한다.
   - 오른쪽에 필요한 모니터 두께가 자동 계산된다. `모니터 = 목표 ÷ ratio`
   - 아래 줄에 ratio 출처가 나온다.
     - `ratio 0.8123 · calibration 2026-09-10`: 해당 날짜 calibration 값
     - `ratio 0.8123 · ratio 직접 입력`: 목록과 일치하는 calibration이 없는 값
     - `모니터 직접 입력`: 모니터 두께를 손으로 입력한 경우
4. `설정 ✎ O-3 · TF 20` 버튼: 누르면 설정 영역이 열린다. 재료가 비어 있는 새 카드는 처음부터 열려 있다.
5. 측정 표(시작 | 끝): 3.3.7 참고
6. `메모`: 이 레이어의 비고

#### 3.3.6 설정 영역

- `재료`: 입력하면 목록이 나온다.
  - `재료_TF_소스` 형식(예: `CBP_20_O-3`) 항목을 고르면 소스, TF, ratio가 그 calibration 값으로 채워진다.
  - 재료명만 입력하면 이전 소스/TF/ratio를 지우고, 그 재료의 최신 실측 calibration으로 다시 채운다.
- `소스`: `O-1`~`O-9`, `M-1`~`M-3`. 바꾸면 해당 소스/TF 조건의 최신 ratio로 다시 채운다.
- `TF`: 바꾸면 ratio를 다시 찾는다.
- `Ratio`: 직접 고칠 수 있다. 고치면 모니터 두께가 다시 계산된다.
- `모니터(nm)`: 직접 입력하면 자동 계산을 멈춘다(`모니터 두께 직접 입력됨 (지우면 자동 계산)`). 칸을 비우면 다시 자동 계산된다.
- `목표 실제 레이트(Å/s)`: 참고용 계획 레이트. 프리셋에서 시작하면 채워진다.

맞는 calibration이 없으면 ratio가 비고 모니터 두께도 비어 있다. 이때는 Calibration 탭에서 확인하거나 ratio를 직접 입력한다.

#### 3.3.7 측정 표와 시작/끝 버튼

| 행 | 단위 | 비고 |
|---|---|---|
| 압력 | ×10⁻⁷ | 숫자만 입력(예: `3.2`). 저장 시 `3.2x10-7`로 기록 |
| 레이트 | Å/s | |
| 파워 | | `지난 기록 ›` 누르면 과거 기록 |
| 온도 | °C | `지난 기록 ›` 누르면 과거 기록 |

순서:

1. 증착을 시작할 때 `▶ 시작`을 누른다. 버튼 아래에 시각(HH:MM)이 표시되고 카드 테두리가 주황색이 된다.
2. 시작 열에 압력, 레이트, 파워, 온도를 입력한다.
3. 증착이 끝나면 `■ 끝`을 누른다. 시각이 기록되고 카드가 접히며 테두리가 초록색이 된다.
4. 접힌 카드를 펼쳐 끝 열에 값을 입력한다.

- 이미 누른 버튼은 `▶ 시작 ↺`, `■ 끝 ↺`로 바뀐다. 다시 누르면 `시각을 지금으로 바꿀까요?`를 묻는다.
- 시작 후 끝을 누르기 전까지 요약 줄에 `경과 m:ss`가 1초마다 갱신된다. 끝나면 `소요 m:ss`로 바뀐다.
- 진행 중인 레이어가 있고 기록 탭을 보고 있는 동안에는 화면이 꺼지지 않게 요청한다(브라우저가 지원할 때).
- 시각은 파일에 `YYYY-MM-DD HH:MM`으로 저장된다.

흐린 안내 글자(placeholder): 칸이 비어 있을 때만 보이며, 저장되지 않는다. 같은 값이면 직접 입력해야 한다.

- 압력, 레이트 시작 칸의 `이전 3.1`: 바로 앞 레이어의 끝 값
- 파워, 온도 시작 칸의 `지난 12.5`: 같은 재료·같은 소스로 증착한 가장 최근 로그의 시작 값

`파워` 또는 `온도` 글자(`지난 기록 ›`)를 누르면 같은 재료·소스의 최근 5회 기록(날짜, 파워, 온도, 레이트의 시작→끝)이 나온다. 항목을 누르면 그 로그 상세로 이동한다. 소스가 비어 있으면 기록이 나오지 않는다.

툴링 로그에서는 `실측 두께(nm)` 칸이 추가로 보인다. 엘립소미터 측정 후 나중에 로그를 수정해서 넣어도 된다.

#### 3.3.8 구조 패널

오른쪽 위 `구조 n층 ▴/▾` 패널에 현재 기록의 적층 구조가 그려진다.

- 아래가 기판, 위로 갈수록 나중 레이어다.
- 블록 크기는 목표 두께 기준, 오른쪽에 마스크(`M1` 등)가 표시된다.
- 진행 중인 레이어는 주황 테두리, 끝난 레이어는 흐리게 표시된다.
- 블록을 누르면 해당 카드로 스크롤한다. 접힌 카드는 펼쳐진다.
- 패널 제목을 누르면 패널이 접힌다(설정은 기기에 기억됨).
- 맨 아래에 `총 n nm (목표)`가 표시된다.

#### 3.3.9 레이어 추가, 초안

- `+ 레이어 추가`: 맨 끝에 빈 레이어를 추가한다. 마스크는 바로 앞 레이어 값을 따른다.
- `+ 공증착 추가`: 3.5 참고
- 입력값은 자동으로 폰에 초안으로 저장된다. 앱을 닫거나 폰이 꺼져도 다시 열면 이어서 쓸 수 있다.
- `초안 버리기`: 저장하지 않은 입력을 모두 지운다.
- `프리셋으로 저장`: 3.4.2 참고

#### 3.3.10 Dropbox에 저장

1. 화면 아래 `Dropbox에 저장`을 누른다.
2. 저장이 끝나면 상단에 `저장됨: <파일명>`이 표시되고 저장한 로그의 상세 화면이 열린다.
3. 초안은 비워진다.

저장 전 검사:

- 날짜가 6자리가 아니면: `날짜를 YYMMDD 6자리로 입력해 주세요.`
- 재료가 입력된 레이어가 없으면: `재료가 입력된 레이어가 하나 이상 필요해요.`
- 공증착 재료 중 재료명이나 부피비가 빠졌으면: `공증착 재료마다 재료명과 부피비(%)를 입력해 주세요.`

재료가 비어 있는 레이어는 저장에서 빠진다.

저장 위치와 파일명:

```text
Process_General/20YY/YYMMDD/<재료1, 재료2, ...>_general_v11_HHMM.xlsx
Process_Tooling/20YY/YYMMDD/<재료1, 재료2, ...>_tooling_v11_HHMM.xlsx
```

- `HHMM`은 저장 버튼을 누른 시각이다. 같은 날 같은 재료 로그가 겹치지 않게 하기 위한 것이다.
- 재료명에 `\ / : * ? " < > |`가 있으면 파일명에서는 `_`로 바뀐다(예: `Ir(ppy)3`는 그대로, `A/B`는 `A_B`).
- 같은 이름 파일이 이미 있으면 덮어쓰지 않고 `_2`, `_3`을 붙인다.
- 테스트 모드이면 위 경로 앞에 `_mobile_test/`가 붙는다.
- 인터넷이 안 되면 폰에 보관했다가 나중에 올린다(6.1 참고).

### 3.4 프리셋

프리셋은 자주 쓰는 적층 구조(재료, 소스, TF, 목표 두께, 레이트, 마스크, 공증착 비율)를 저장한 파일이다. 양식은 Structure 파일과 같다.

#### 3.4.1 프리셋에서 시작

1. `기록` 탭 첫 화면의 `프리셋에서 시작`에서 검색창에 이름을 입력한다.
2. 목록에는 `프리셋`(Presets 폴더)과 `Structure`(Structures 폴더) 파일이 함께 나온다. Structure 파일도 프리셋처럼 쓸 수 있다.
3. `일반증착으로` 또는 `툴링으로`를 누른다.
4. 레이어 카드가 자동으로 만들어진다.
   - 재료, 소스, TF, 마스크, 목표 실제 두께, 목표 실제 레이트가 채워진다.
   - ratio는 소스/TF 조건에 맞는 최신 calibration으로 채워지고, 모니터 두께가 계산된다.
   - `co-dep` 행은 공증착 카드가 되고, 재료별 목표 두께와 레이트는 부피비로 나뉜다.
5. 측정값만 입력하며 기록한다.

프리셋 적용 후에도 카드별로 값을 바꿀 수 있다. 프리셋 파일 자체는 바뀌지 않는다.

#### 3.4.2 프리셋으로 저장

1. 기록 화면에서 `프리셋으로 저장`을 누른다.
2. 프리셋 이름을 입력한다(기존 프리셋에서 시작했다면 그 이름이 기본값).
3. 같은 이름이 있으면 `"이름" 프리셋이 이미 있어요. 덮어쓸까요?`를 묻는다.
4. `Presets/<이름>.xlsx`로 저장된다(테스트 모드면 `_mobile_test/Presets/`).

저장되는 값: 재료, 소스, TF, 목표 두께(공증착은 합계), 레이트(목표 레이트, 없으면 시작 레이트), 마스크, 공증착 부피비. 측정값과 시각은 저장되지 않는다. 파일에는 `Info` 시트(이름, 작성자, 시각, 앱)가 함께 들어간다.

#### 3.4.3 프리셋 삭제

1. 프리셋 목록에서 `삭제`를 누른다(Structure 항목에는 삭제 버튼이 없다).
2. 확인하면 삭제된다. Dropbox 휴지통에서 복구할 수 있다.

테스트 모드에서는 실제 폴더의 프리셋을 지울 수 없다.

### 3.5 공증착

#### 3.5.1 공증착 카드 만들기

1. 기록 화면에서 `+ 공증착 추가`를 누른다. 재료 2개짜리 공증착 카드가 추가되고 설정 영역이 열린다.
2. 재료마다 `재료`, `소스`, `TF`, `부피비(%)`를 입력한다. `Ratio`는 재료를 고르면 자동으로 채워진다.
3. 재료가 3개면 `+ 재료 추가`를 누른다. 최대 3개까지 가능하다. 3개일 때는 각 재료에 `빼기` 버튼이 생긴다.
4. 파란 상자의 `nm (목표 합계)` 칸에 공증착층 전체 목표 두께를 입력한다.
5. 재료별로 `목표 두께 → 모니터 두께`가 계산되어 표시된다.
   - 재료 목표 두께 = 합계 × (부피비 ÷ 부피비 합)
   - 모니터 두께 = 재료 목표 두께 ÷ 재료 ratio

부피비 합이 100이 아니어도 비율로 나눈다(예: 94와 6, 또는 47과 3은 같은 결과).

#### 3.5.2 공증착 측정 입력

공증착 카드에서 함께 쓰는 값과 재료별 값은 다음과 같다.

| 함께 쓰는 값 (한 번만 입력) | 재료별 값 |
|---|---|
| 마스크 | 레이트 (시작/끝) |
| ▶ 시작 / ■ 끝 시각 | 파워 (시작/끝) |
| 압력 (시작/끝) | 온도 (시작/끝) |
| 메모 | 실측 두께 (툴링) |

측정 표 아래에 `현재 부피비 (끝 레이트) 94.2 : 5.8` 같은 문구가 실시간으로 표시된다.

- 계산: 재료별 (입력한 모니터 레이트 × ratio)를 합으로 나눈 비율
- 모든 재료의 끝 레이트가 있으면 끝 레이트로, 아니면 시작 레이트로 계산한다.
- 목표 부피비와 차이가 나면 레이트를 조정한다.

#### 3.5.3 저장 형식

공증착층은 재료마다 한 레이어(시작/끝 행 쌍)로 저장된다. 각 재료의 비고 앞에 `co-dep CBP:Ir(ppy)3 (94 vol%)` 형식의 태그가 붙고, X열에 그룹 표시가 들어간다(5.3 참고). PC 앱에서는 재료별 레이어로 보인다.

### 3.6 Calibration 탭

#### 3.6.1 재료 목록

1. `Calibration` 탭을 누른다.
2. 검색창에 재료명을 입력한다.
3. 재료마다 `TF 20 · O-3   0.8123  2026-09-10`처럼 TF·소스 조합별 최신 실측 ratio와 날짜가 보인다. 실측이 없는 조합은 `실측 없음`으로 표시된다.

계산 규칙은 PC v11(v10 수정 포함)과 같다. 툴링 로그의 실측값도 포함된다.

#### 3.6.2 재료 상세와 계산

1. 재료를 누른다.
2. TF·소스 조합 카드마다 ratio, `모니터 x → 실측 y nm`, 날짜가 보인다.
3. 카드를 누르면 계산 칸이 열린다.
   - `목표 실제 두께 (nm)` 입력 → `필요 모니터 두께`
   - `목표 실제 레이트 (Å/s)` 입력 → `모니터 레이트`
4. 아래 `기록` 표에 날짜, Ratio, TF, 소스, 모니터, 실측, 레이트 이력이 있다.

#### 3.6.3 실측 추가

1. 재료 상세에서 계산하려는 조합 카드를 먼저 선택한다(선택하지 않으면 첫 번째 조합 기준).
2. `+ 실측 추가`를 누른다.
3. 입력: `날짜 (YYMMDD)`(오늘 자동), `소스`, `TF`(선택한 조합 값 자동), `레이트`, `모니터 두께(nm)`, `실측 두께(nm)`, `압력`, `파워`, `메모`
4. 모니터와 실측을 입력하면 `Ratio x`가 미리 보인다.
5. `저장`을 누른다.

- 저장 위치: `Calibration/<재료명>/YYMMDD.xlsx` (테스트 모드면 `_mobile_test/` 아래)
- 같은 날짜 파일이 있으면 덮어쓸지 묻는다. 같은 날 두 번째 측정이면 취소하고 PC에서 정리한다.
- 메모 뒤에 `입력: <작성자> (<기기>)`가 자동으로 붙는다.
- 필수값 오류: `재료명과 YYMMDD 날짜는 필수입니다.`, `Monitor/Actual thickness 숫자가 필요합니다.`

### 3.7 설정 탭

| 항목 | 내용 |
|---|---|
| 작성자 | 이름을 고치고 `변경`. 이후 저장하는 파일부터 적용 |
| 저장 위치 | `테스트 폴더(_mobile_test)에만 저장` 스위치 |
| Dropbox 폴더 | 기준 폴더 경로. 바꾸고 `저장 후 다시 동기화`하면 캐시를 지우고 전부 다시 받음. 보통 바꾸지 않음 |
| 캐시 | 파일 수, 마지막 동기화 시각, 실패 수. `전체 다시 받기`, `로그아웃` |
| 버전 | 하단 `버전 YYYY-MM-DD-xxxxxxxx` |

#### 3.7.1 테스트 모드

켜져 있을 때:

- 폰에서 저장, 수정, 삭제하는 모든 파일이 `VTE_MANAGER/_mobile_test/` 안에만 생긴다.
- 테스트 파일도 목록에 원래 위치처럼 보이고 `테스트` 배지가 붙는다.
- 실제 폴더 파일을 수정하면 테스트 폴더에 새 파일로 저장된다(원본 그대로).
- 실제 폴더의 로그와 프리셋은 삭제할 수 없다.

꺼져 있을 때:

- 실제 로그 폴더에 저장된다.
- `_mobile_test` 파일은 로그, calibration, 프리셋 목록에서 모두 숨겨진다. 테스트 calibration이 실제 ratio 계산에 섞이지 않는다.

끌 때는 `테스트 모드를 끄면 폰에서 저장하는 파일이 실제 로그 폴더에 생겨요. 끌까요?`를 확인한다.

#### 3.7.2 로그아웃

`로그아웃`은 로그인 정보와 이 기기의 캐시(받은 파일, 초안, 업로드 대기 포함)를 지운다. 업로드 대기가 있으면 먼저 올린 뒤 로그아웃한다.

## 4. PC v11 사용법

PC v11의 화면과 기본 사용법은 v9와 같다. 이 장은 v9 이후 바뀐 점을 중심으로 설명한다. 바뀌지 않은 부분은 v9 매뉴얼의 해당 절을 본다.

### 4.1 v9 대비 바뀐 점 요약

| 구분 | 내용 |
|---|---|
| 제목/탭 | `VTE Log Manager v11`, `새 프로세스 로그 v11` 탭 |
| 새 파일 이름 | `_general_v11.xlsx`, `_tooling_v11.xlsx`, `YYMMDD_structure_v11.xlsx` |
| Calibration/툴링 탭 | 여러 재료가 들어 있는 툴링 로그를 재료별로 정확히 읽음 (v10 수정) |
| 툴링 로그 저장 | end 행 J열에 목표값을 더 이상 쓰지 않음 (v10 수정) |
| 레이어 입력 표 | 행별 `앞에 삽입`/`삭제`, `추가 위치` 선택, `삭제 되돌리기` |
| Structure 탭 | `프리셋으로 저장` 버튼 추가 |
| 폰 파일 | 폰에서 저장한 로그(작성자, 시작/끝 시각, 공증착 표시)를 그대로 읽음 |
| 기존 파일 | v7/v9/v10 파일 형식 변경 없음. 변환 불필요 |

### 4.2 Calibration / 툴링 탭 (v10 수정 내용)

v9에서는 여러 재료 툴링 로그의 열 위치를 잘못 읽어 Power, Rate, Monitor 값이 밀리고 ratio가 틀리게 나올 수 있었다. v10부터 다음과 같이 고쳐졌고 v11에 포함되어 있다.

- 툴링 로그는 파일 전체에서 헤더를 찾고, 선택한 재료의 행만 읽는다.
- 공증착 `A:B` 레이블 행이면 `/`로 나뉜 값 중 해당 재료 값을 쓴다.
- Source, TF는 그 행의 B열, R열 값을 쓴다. 없으면 파일 상단 재료 목록과 `재료 Tooling Factor` 행에서 가져온다.
- 실측 = start 행 J열, Monitor = end 행 I열.
- 실측이 없는 툴링 기록은 표에 `실측 없음`으로 표시하고 ratio 계산에서 뺀다.
- 최신 calibration은 파일 단위가 아니라 측정 단위로 고르고, 실측 ratio가 있는 값을 우선한다.
- 파일명에 날짜가 없으면 날짜를 빈칸으로 둔다.

따라서 `Latest ratio`, 재료 목록 자동 채우기, Structure 계산 결과가 v9와 다를 수 있다. v11(및 폰 앱) 값이 맞다.

### 4.3 새 프로세스 로그 v11 탭

사용법은 v9 매뉴얼 5장과 같다. 달라진 점:

1. 첫 열 `레이어 / 작업`에 행 번호와 `앞에 삽입`, `삭제` 버튼이 있다.
2. 상단 `추가 위치`에서 `맨 끝` 또는 `n번 앞`을 고른 뒤 `+ 레이어 추가`를 누르면 그 위치에 빈 행이 들어간다.
3. `- 마지막 삭제` 또는 행의 `삭제`로 지운 행은 `삭제 되돌리기`로 되살릴 수 있다(여러 번 가능).
4. 저장 파일명은 `<재료목록>_general_v11.xlsx` / `_tooling_v11.xlsx`이다. PC 저장 파일명에는 폰과 달리 시각(`_HHMM`)이 붙지 않는다.
5. 툴링 로그의 `측정실제`는 start 행 J열에만 저장된다.

`저장`, `다른 이름으로 저장`, `로그 생성 (Excel)`의 덮어쓰기 확인 동작은 v9와 같다.

### 4.4 폰에서 저장한 로그를 PC에서 볼 때

- 뷰어 목록에 `..._general_v11_HHMM.xlsx` 형식으로 나온다.
- 상세 모달의 Layer data는 기존 로그와 같게 표시된다.
- 공증착층은 재료별 행으로 보이고, 비고에 `co-dep CBP:Ir(ppy)3 (94 vol%)` 태그가 보인다.
- 작성자, 기기, 시각 정보는 W열 이후에 있어 PC 화면에는 표시되지 않는다. Excel로 열면 볼 수 있다.
- 폰 테스트 폴더(`_mobile_test`)는 PC 앱이 읽지 않는다.

PC v11에서 폰 로그를 `편집` 후 `저장`해도 폰이 남긴 정보(작성자/기기/시각 메타, 시작/끝 시각, 끝 레이트, 공증착 표시)는 그대로 유지된다. 메타에는 `Modified By: PC v11`과 수정 시각이 추가된다. PC에서 레이트를 바꾸면 폰에서 적은 끝 레이트는 새 레이트로 바뀐다. v9/v10으로 편집·저장하면 이 정보가 빠지므로 폰 로그는 v11이나 폰에서 수정한다.

### 4.5 Structure 탭: 프리셋으로 저장

1. `OLED Structure Manager` 탭에서 구조를 입력한다(v9 매뉴얼 7장).
2. `프리셋으로 저장`을 누른다.
3. 프리셋 이름을 입력한다. 파일명에 쓸 수 없는 문자는 `_`로 바뀐다.
4. 같은 이름이 있으면 `<이름>.xlsx 이미 존재. 덮어쓸까요?`를 묻는다.
5. `Presets/<이름>.xlsx`로 저장되고 `프리셋 저장됨: Presets/<이름>.xlsx`가 표시된다.

- `Mat1`이 비어 있는 행은 저장되지 않는다.
- 폰 앱의 `프리셋에서 시작` 목록에 나타난다(폰에서 동기화 후).
- PC에는 프리셋 목록 화면이 따로 없다. 프리셋을 고치려면 `Structure 열기`로 `Presets` 폴더의 파일을 열어 수정한 뒤 `저장`한다. 이때 `Info` 시트는 빠지고 구조 시트만 남는다(프리셋으로는 계속 쓸 수 있다).
- `Structures` 폴더의 기존 structure 파일도 폰에서 프리셋으로 바로 쓸 수 있으므로, 꼭 프리셋으로 복사할 필요는 없다.

### 4.6 바뀌지 않은 부분

| 내용 | v9 매뉴얼 |
|---|---|
| 폴더 스캔, 날짜 인식, 숫자 입력 | 3장 |
| 프로세스 로그 뷰어(필터, 정렬, 상세, 삭제) | 4장 |
| Calibration 추가/수정/삭제 모달, Calibration 파일 양식 | 6.6~6.10 |
| Structure 입력, 계산, 열기/저장/삭제 | 7장 (저장 파일명만 `_structure_v11`) |
| 오류 메시지와 해결 | 9장 |

주의(v9와 동일): Calibration 이력에는 툴링 로그에서 읽은 행도 있다. `선택 삭제` 전에 `파일` 열 경로를 꼭 확인한다.

## 5. 파일 형식과 호환성

### 5.1 원칙

- 폰에서 저장한 로그는 PC 로그와 같은 배치(A~V열)를 쓴다. v10 앱도 같은 결과로 읽는다(테스트로 확인).
- 추가 정보는 W열 이후에만 넣는다. 로그 파서와 calibration 판독은 W열 이후를 보지 않는다.
- 기존 v7/v9/v10/fromExcel 파일은 건드리지 않는다. 앱이 자동 변환하지 않는다.

### 5.2 폰 로그 파일의 추가 정보

1행 W열부터 `이름, 값` 쌍이 두 칸씩 들어간다. 값이 있는 항목만 쓴다.

| 항목 | 새 로그 | 수정 저장 |
|---|---|---|
| `App` | `VTE Log PWA <버전>` | 새 버전으로 갱신 |
| `Author` | 작성자 이름 | 유지 |
| `Device` | `iPhone`, `iPad`, `Android`, `Mac`, `Windows`, `Browser` | 수정한 기기로 갱신 |
| `Created At` | 기록 시작 시각 `YYYY-MM-DD HH:MM` | 유지 |
| `Preset` | 프리셋 이름 | 유지 또는 갱신 |
| `Modified By` | - | 수정자 이름 |
| `Modified At` | - | 수정 시각 |

`Created At`은 저장 시각이 아니라 초안을 시작한 시각이다.

데이터 영역:

- 헤더 행 W열: `Time (start row / end row)` (시각이 있을 때)
- 각 레이어 start 행 W열: 시작 시각, end 행 W열: 끝 시각
- 헤더 행 X열: `Co-dep (group vol%)` (공증착이 있을 때)
- 공증착 재료의 start 행 X열: `co-dep <그룹번호> <부피비>` (예: `co-dep 1 94`)
- 공증착 재료의 비고(K열) 앞: `co-dep CBP:Ir(ppy)3 (94 vol%)` 태그

레이트는 start 행 H열에 시작 레이트, end 행 H열에 끝 레이트가 들어간다(끝 레이트가 없으면 시작 레이트와 같게 저장). 압력은 `x10-7`이 붙어 저장된다.

### 5.3 파일명 비교

| 종류 | PC v9 | PC v11 | 폰 |
|---|---|---|---|
| 일반증착 | `재료_general_v9.xlsx` | `재료_general_v11.xlsx` | `재료_general_v11_HHMM.xlsx` |
| 툴링 | `재료_tooling_v9.xlsx` | `재료_tooling_v11.xlsx` | `재료_tooling_v11_HHMM.xlsx` |
| Calibration | `Calibration/재료/YYMMDD.xlsx` | 같음 | 같음 |
| Structure | `YYMMDD_structure_v9.xlsx` | `YYMMDD_structure_v11.xlsx` | 만들지 않음 |
| 프리셋 | 없음 | `Presets/이름.xlsx` | `Presets/이름.xlsx` |

충돌로 새 파일이 된 경우 `_copy`, `_2`, `_3` 등이 붙을 수 있다(6.3).

### 5.4 프리셋 파일

- 첫 시트: Structure와 같은 양식. 1행 헤더 `mode, mat1, src1, tf1, vol1, mat2, src2, tf2, vol2, mat3, src3, tf3, vol3, thick, rate, mask`, 이후 한 행이 한 층
- 두 번째 시트 `Info`: `Name`, `Author`(폰), `Created At` 또는 `Updated At`, `App`
- PC `Structure 열기`로 열 수 있고, 폰에서는 `Structures` 파일과 같은 방식으로 읽는다.

### 5.5 v9 앱으로 새 파일을 열 때

v9 앱은 v10 이후 툴링 로그의 calibration 값을 여전히 틀리게 읽는다. 모든 PC를 v11로 바꾼다.

## 6. 오프라인, 업데이트, 충돌

### 6.1 오프라인에서 기록하기

- 로그 조회와 Calibration 조회는 마지막 동기화 데이터로 오프라인에서도 된다.
- 기록 입력은 원래 폰에 초안으로 저장되므로 인터넷과 무관하다.
- 오프라인에서 `Dropbox에 저장`, `프리셋으로 저장`, 실측 `저장`을 누르면 폰에 보관한다.
  - `인터넷이 안 돼서 폰에 보관했어요. 연결되면 자동으로 Dropbox에 올려요.`
- 로그 삭제, 프리셋 삭제는 오프라인에서 할 수 없다.

### 6.2 업로드 대기

보관된 항목이 있으면 상단에 `업로드 대기 n건` 배너가 뜬다(실패가 있으면 `· 실패 n건`, 오프라인이면 `(오프라인)`).

자동 재시도 시점:

- 인터넷이 다시 연결될 때
- 앱을 다시 화면에 띄울 때
- 동기화가 끝났을 때

올라가면 `대기 중이던 n건 업로드 완료`가 표시되고 배너가 사라진다.

`보기`를 누르면 대기 목록이 나온다.

- `지금 올리기`: 바로 재시도
- `초안으로 되돌리기`(로그만): 업로드를 취소하고 다시 편집 가능한 초안으로 만든다. 작성 중인 다른 초안이 있으면 버릴지 묻는다.
- `버리기`: 폰에 보관된 내용을 지운다. 되돌릴 수 없다.

실패 표시가 있는 항목은 네트워크가 아닌 이유(권한, 경로 등)로 실패한 것이다. 오류 문구를 캡처해 관리자에게 보낸다.

주의: 업로드 대기와 초안은 그 폰의 앱 안에만 있다. 앱 삭제, 로그아웃, 브라우저 데이터 삭제 전에 반드시 업로드를 끝낸다.

### 6.3 충돌 처리

폰 앱은 Dropbox 파일을 절대 몰래 덮어쓰지 않는다.

| 상황 | 동작 |
|---|---|
| 새 로그 저장 시 같은 이름 파일이 있음 | `_2`, `_3`을 붙여 새 파일로 저장 |
| 수정 저장 시 그 사이 다른 기기가 파일을 수정함 | `다른 기기에서 먼저 수정된 로그예요. 덮어쓰지 않고 새 파일로 저장할까요?` 확인 후 새 파일(현재 날짜/재료/시각 이름)로 저장 |
| 프리셋/실측 덮어쓰기 중 다른 기기가 먼저 수정함 | 확인 후 `_copy`가 붙은 새 파일로 저장 |
| 업로드 대기 항목이 충돌 | 묻지 않고 새 파일로 저장 |
| 수정 중 원본이 삭제됨 | 새 파일로 저장 |
| 삭제 시 그 사이 수정/삭제됨 | 삭제하지 않고 알림 |

충돌로 파일이 두 개가 되면 PC나 폰에서 내용을 비교해 필요 없는 쪽을 지운다. PC 앱은 이 확인을 하지 않고 덮어쓰기 확인창만 띄우므로, 같은 파일을 PC와 폰에서 동시에 고치지 않는다. PC 쪽에서 동시에 저장되면 Dropbox가 `충돌 사본`(conflicted copy) 파일을 만들 수 있다.

### 6.4 앱 업데이트

- 앱을 열 때와 다시 화면에 띄울 때 새 버전을 확인한다.
- 새 버전이 받아지면 상단에 `새 버전이 있어요 · 적용`이 뜬다.
- `적용`을 누르면 입력 중인 초안을 먼저 저장하고 앱을 새로 고친다. 초안은 유지된다.
- 현재 버전은 `설정` 맨 아래에 있다.

## 7. 문제 해결 FAQ

### 7.1 폰 앱

**Q. `Dropbox 앱에 파일 권한이 없어요.`가 나온다.**
관리자가 Dropbox 앱 권한을 설정해야 한다(8.1). 설정 후 다시 로그인한다.

**Q. `로그인이 만료됐어요. 다시 로그인해 주세요.`가 나온다.**
`Dropbox 로그인`을 다시 한다. Dropbox에서 앱 연결이 해제된 경우에도 나온다. 초안과 업로드 대기는 남아 있다.

**Q. `Dropbox 폴더를 찾지 못했어요 — 설정에서 경로 확인`이 나온다.**
`설정 > Dropbox 폴더`가 `/NEXT LAB/Log/A222/VTE log/VTE_MANAGER`인지 확인한다(대소문자, 띄어쓰기 포함). 공용 계정이 아닌 개인 계정으로 로그인했을 수도 있다.

**Q. 빨간 `동기화 오류` 상자가 나온다.**
화면을 캡처해 관리자에게 보낸다. 그동안 캐시된 데이터로 조회와 기록은 계속할 수 있다.

**Q. PC에서 방금 저장한 로그가 폰에 안 보인다.**
PC의 Dropbox 동기화가 끝났는지 확인한 뒤 폰 상단 ⟳을 누른다. 그래도 안 보이면 `설정 > 전체 다시 받기`.

**Q. 폰에서 저장했는데 PC/다른 사람에게 안 보인다.**
1. 테스트 모드가 켜져 있었는지 확인한다. 켜져 있었다면 파일은 `_mobile_test/` 안에 있다.
2. 상단에 `업로드 대기` 배너가 있는지 확인한다.
3. PC Dropbox 동기화 후 PC 앱에서 `새로고침`을 누른다.

**Q. 테스트 모드에서 저장한 로그를 실제 폴더로 옮기고 싶다.**
테스트 모드를 끈 뒤 테스트 로그는 목록에서 숨겨지므로 앱에서는 옮길 수 없다. 테스트 모드에서 해당 로그 내용을 확인해 두고, 테스트 모드를 끈 뒤 새로 기록하거나, PC Dropbox 폴더에서 파일을 직접 옮긴다.

**Q. ratio가 비어 있고 모니터 두께가 계산되지 않는다.**
해당 재료·소스·TF 조합에 실측 calibration이 없다. `설정 ✎`에서 소스/TF를 확인하거나, 재료 칸에서 `재료_TF_소스` 항목을 고르거나, Ratio를 직접 입력한다.

**Q. ratio 옆에 `ratio 직접 입력`이 나온다.**
현재 ratio가 그 소스/TF의 calibration 기록과 일치하지 않는다. 손으로 입력했거나 이전 재료 값이 남은 경우다. 재료를 다시 고르면 최신 값으로 바뀐다.

**Q. `지난 기록`에 아무것도 안 나온다.**
소스를 선택하지 않았거나, 같은 재료·같은 소스 로그가 없다.

**Q. 기록 중 화면이 꺼진다.**
`▶ 시작`을 누른 레이어가 있고 기록 탭을 보고 있을 때만 화면 꺼짐을 막는다. 폰 기종/OS에 따라 지원되지 않을 수 있다. 저전력 모드도 영향을 줄 수 있다.

**Q. 앱을 닫았다 열었더니 입력이 사라졌을까?**
초안은 입력할 때마다 자동 저장된다. `기록` 탭을 누르면 이어서 보인다. 로그아웃, 앱 삭제, 브라우저 데이터 삭제를 하면 사라진다.

**Q. 삭제 버튼을 누르면 `테스트 모드에서는 실제 로그 폴더의 파일을 지울 수 없어요.`가 나온다.**
의도된 동작이다. 실제 파일을 지우려면 테스트 모드를 끈다.

**Q. `파일 버전 정보가 없어 삭제하지 않았어요.`가 나온다.**
⟳로 동기화한 뒤 다시 삭제한다.

**Q. 새 버전 배너가 계속 안 뜬다.**
앱을 완전히 닫았다가 다시 연다. 그래도 안 되면 잠시 후 다시 열어 본다.

### 7.2 PC 앱

**Q. Windows에서 설치 창에 `The installation files are incomplete.`가 나온다.**
ZIP 안에서 바로 실행한 것이다. ZIP을 완전히 압축 해제한 뒤 다시 실행한다.

**Q. 화면은 열리는데 Excel 기능이 안 된다.**
설치본은 `app\vendor\xlsx.full.min.js` 파일이 있는지 확인한다. 단일 HTML 파일이면 인터넷 연결을 확인한다.

**Q. 저장이 안 된다.**
앱을 다시 열고 `폴더 선택`에서 쓰기 권한을 다시 허용한다.

**Q. Calibration 탭 ratio가 v9와 다르다.**
v10에서 고친 판독 오류 때문이다(4.2). v11 값을 쓴다.

**Q. 폰에서 만든 프리셋을 PC에서 쓰고 싶다.**
`Structure 열기`로 `Presets` 폴더의 파일을 연다.

## 8. 관리자 메모

### 8.1 Dropbox 앱

- 랩 공용 Dropbox 계정에 등록한 개발자 앱을 쓴다. 로그인은 PKCE 방식이라 앱 비밀키가 필요 없고, 코드에 들어 있는 앱 키는 공개되어도 되는 값이다. 토큰, 비밀번호는 이 문서나 저장소에 적지 않는다.
- Permissions 탭에서 다음 세 권한을 체크하고 `Submit`한다.
  - `files.metadata.read`
  - `files.content.read`
  - `files.content.write`
- 권한을 바꾼 뒤에는 모든 기기에서 다시 로그인해야 새 권한이 적용된다.
- 로그인 후 돌아오는 주소(Redirect URI)는 앱 주소 `https://swag1129-oss.github.io/vte-log-manager/`이다. 주소를 바꾸면 Dropbox 앱 설정의 Redirect URI도 같이 바꾼다.
- 앱 권한 범위는 Dropbox 전체이지만, 앱 코드가 `VTE_MANAGER` 밖 경로 요청을 막는다.
- 폰 분실 시: Dropbox 계정 설정에서 이 앱 연결을 해제한다. 공용 계정이라 기기별 해제가 안 되므로 모든 기기가 다시 로그인해야 한다. 분실 폰의 업로드 대기/초안은 복구할 수 없다.

### 8.2 GitHub Pages 배포

- 저장소: `swag1129-oss/vte-log-manager`
- Pages 설정: `main` 브랜치의 `/docs` 폴더
- 배포 순서
  1. `src/mobile`, `src/core`를 수정한다.
  2. `npm test`로 빌드와 테스트를 실행한다(`docs/`가 다시 만들어진다).
  3. `docs/`를 포함해 `main`에 커밋하고 푸시한다.
  4. 몇 분 뒤 폰에서 앱을 열면 `새 버전이 있어요 · 적용` 배너가 뜬다.
- 버전 문자열은 빌드 날짜와 파일 해시로 자동 생성된다(`설정` 하단 표시).
- PC 단일 파일: `npm run build` → `dist/vte_manager_v11.html`
- Windows 패키지: `npm run build:windows`
- 실제 랩 데이터 파일은 저장소에 커밋하지 않는다.

### 8.3 테스트 모드 운영

- 새 기기의 기본값은 테스트 모드 켜짐이다. 새 멤버는 테스트 모드로 연습한 뒤 끄도록 안내한다.
- 테스트 모드 파일은 `VTE_MANAGER/_mobile_test/` 아래 실제와 같은 폴더 구조로 생긴다.
- 테스트 모드를 끈 기기에서는 `_mobile_test` 파일이 보이지 않고, 테스트 calibration이 실제 ratio 계산에 쓰이지 않는다.
- PC 앱은 `_mobile_test`를 읽지 않는다.
- `_mobile_test` 폴더는 필요 없으면 PC Dropbox에서 직접 정리해도 된다. 실제 데이터에는 영향이 없다.
- 실제 증착 기록은 반드시 테스트 모드를 끄고 저장하도록 안내한다.
